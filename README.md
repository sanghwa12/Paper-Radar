# Paper Radar

현재는 같은 앱 안에서 **리뷰 Radar**를 개발한다. 최근 3년의 분야·방법 리뷰를 검색하고, 짧은 카드로 살펴본 뒤 관심 리뷰의 깊은 상세 브리핑에서 핵심 원저로 연결한다. 상세는 **요약 / 방법 비교 / 근거와 원저 / 그림·한계 / 연구 적용**의 5개 탭으로, 방법의 가정·비교·수치·한계와 실제 검토한 출처를 함께 설명한다. 기존 원저 중심 개발은 보류하고 자료와 개인 기록을 보존한다. 새 기준과 구현 범위는 [REVIEW_RADAR_PLAN.md](REVIEW_RADAR_PLAN.md)를 따른다.

시범 리뷰 1편은 공개 원고 본문과 실제 Figure 1을 확인했다. 연결 원저 3편은 초록 중심이며 본문 전체·SI·원자료 재현은 미검증이다. 추가 보조 출처의 검토 범위는 각각 표시하고 전체 상태는 **일부 검토**로 유지한다. 화면의 학습용 개념도는 분석자의 설명이며 원문 그림이나 실측 데이터가 아니다.

의약화학·신약개발 논문을 카드로 살펴보고 관심 논문의 상세 내용과 연구 적용 아이디어를 기록하는 로컬 앱입니다. 기존 AdaptiveFlow 2026·Sung 2025 사례, 6개 분야 시범 논문 12편, 준비 자료에서 새로 작성·검토한 PK 논문 1편을 제공합니다.

시범 12편의 현재 검토 상태는 모두 **일부 검증 · 초안**입니다. 확보한 파일과 실제로 확인한 내용을 구분하며, 원문·SI 미확보 또는 미검토 범위가 남아 있습니다. 논문별 범위는 [BRIEF_VERIFICATION.md](BRIEF_VERIFICATION.md), 작성·검증 원칙은 [BRIEFING_GUIDELINES.md](BRIEFING_GUIDELINES.md)를 참고합니다.

**생성 비교**에서는 MTS(실험·평가 기술)와 Zavegepant PBPK(ADME·PK/PD) 2편의 기존 브리핑과 현재 Codex에서 원자료로 새로 작성한 시범본을 비교합니다. 논문 선택에서 대상을 바꾸며 두 버전은 별도로 보관합니다. 기존 Library를 덮어쓰지 않고, 외부 API 및 상시 생성 연결과는 구분합니다. [시범 결과와 남은 범위](data/generation-pilot/README.md)를 참고합니다.

## 실행과 재시작

Python 3.10 이상이 필요합니다. 개발 환경에서는 Python 3.13.9로 실행했습니다. 기본 열람은 표준 라이브러리로 동작하며, 새 브리핑 자료 준비에는 PDF 텍스트 추출용 `pypdf`와 이미지 확인용 `Pillow`를 사용합니다. API 키와 `npm` 설치는 필요하지 않습니다. 새 PC에서는 한 번만 다음을 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

현재 개발 PC에는 위 환경이 준비되어 있습니다. Windows 실행기와 `start.ps1`은 프로젝트의 `.venv`가 있으면 우선 사용합니다.

Windows에서는 프로젝트 폴더의 **`Paper Radar.cmd`를 더블클릭**하면 됩니다. 서버가 꺼져 있으면 백그라운드에서 실행한 뒤 기본 브라우저를 열고, 이미 실행 중이면 그 서버를 그대로 사용합니다. 브라우저를 닫아도 서버는 유지됩니다. PC를 재시작한 뒤에는 실행기를 다시 더블클릭합니다.

실행에 실패하면 안내 창이 열린 채로 남습니다. 서버 로그는 `.runtime/launcher-server.log`에서 확인합니다. 8765 포트를 다른 프로그램이 사용 중이면 그 프로그램을 종료하거나 변경하지 않고 오류를 안내합니다.

터미널에서 직접 실행하려면 프로젝트 폴더에서 다음 명령을 사용합니다.

```powershell
.\.venv\Scripts\python.exe server.py
```

브라우저에서 [http://127.0.0.1:8765](http://127.0.0.1:8765)를 엽니다. 서버 터미널은 사용 중에 열어 둡니다. 종료는 `Ctrl+C`, 재시작은 같은 명령입니다.

PowerShell에서는 다음 명령도 사용할 수 있습니다.

```powershell
.\start.ps1
```

8765 포트가 이미 사용 중이면 다른 포트로 실행한 뒤 [http://127.0.0.1:8766](http://127.0.0.1:8766)에 접속합니다.

```powershell
.\.venv\Scripts\python.exe server.py --port 8766
```

서버는 이 PC의 `127.0.0.1`에만 연결됩니다. HTML 파일을 직접 여는 대신 위 주소로 접속해야 저장 기능을 사용할 수 있습니다.

## 사용하기

- **[리뷰 Radar](http://127.0.0.1:8765/#/review-radar)**에서 최근 3년의 분야·방법 리뷰를 검색합니다. 분야와 선택 검색어를 정해 직접 검색하며, 최대 30건의 메타데이터를 미리 봅니다. 검색 결과를 DB에 자동 저장하거나 원문을 다운로드하지 않습니다. 등록한 시범 리뷰의 짧은 카드에서 5개 탭의 상세 브리핑과 핵심 원저 3편의 인용 위치로 이동합니다. 리뷰 Figure 1 확인과 연결 원저의 초록 중심 검토, 본문 전체·SI 미검토 범위를 구분해 표시합니다.
- **기존 원저 작업 · 보류**를 펼치면 이전 카드·수집·평가·회차 화면을 계속 사용할 수 있습니다. 아래는 보존한 원저 기능의 사용법입니다.
- **논문 카드**에서 준비된 카드 13편을 먼저 확인합니다. 기본 순서는 6개 분야를 번갈아 보여주며 검색·분야·읽음·저장 상태로 좁힐 수 있습니다. 카드의 연구 목적, 방법→결과, 동향상 의미·적용·한계를 보고 필요한 논문만 **상세 브리핑** 또는 **원문**으로 이동합니다.
- 카드의 Abstract는 펼쳐서 한국어 전문 번역을 봅니다. 참고 점수·IF·인용수는 기존 시범 평가 값을 간략히 표시합니다. 카드 작성 당시의 근거와 현재 상세 브리핑 검토 상태를 구분합니다. 연구 흐름 요약은 설명용이며 원논문 Figure를 대신한 실험 증거가 아닙니다.
- 이번 카드 12편은 확보한 본문과 기존 검토 자료를 읽어 작성해 저장한 결과입니다. 새로 수집되는 모든 후보를 앱이 계속 자동 번역·작성하는 모델 연결은 아직 없습니다. 원문은 사용자가 링크를 눌렀을 때만 열립니다.
- 목록에서 분야·발행일로 필터링하고 제목·키워드·저자·DOI로 검색합니다. 최근 발행순과 과거 발행순을 선택할 수 있습니다.
- Research areas의 `ⓘ` 또는 필터의 **분야 설명**에서 각 분야의 범위와 확인할 점을 볼 수 있습니다. 분야 선택 시 설명이 필터 아래에 표시되며, 한 논문에 여러 분야가 적용될 수 있습니다.
- 카드에서 Abstract 전문을 펼치거나 **상세 브리핑**으로 이동합니다. 상세 화면은 **요약 / 방법과 결과 / Methods / 그림·한계 / 내 메모**의 5개 탭입니다.
- 상세 화면의 **자료 확보·검토 범위**를 펼치면 초록·본문·그림·SI의 확보 여부와 실제 확인 범위, 남은 항목을 볼 수 있습니다. 기본 화면에는 간략한 상태만 표시합니다. 자료를 열거나 다운로드해도 검토 완료로 바뀌지 않습니다.
- 상단 **뒤로가기**로 이전 화면과 목록의 검색·필터·읽던 위치로 돌아갑니다. 상세 주소로 바로 접속한 경우에는 목록으로 이동합니다.
- **읽음 표시**와 **저장**을 누르면 상태가 즉시 저장됩니다. 왼쪽 목록에서 저장한 논문이나 읽지 않은 논문만 볼 수 있습니다.
- 메모는 입력 후 자동 저장됩니다. **메모 저장**으로 즉시 저장할 수도 있습니다. 종료하기 전에 **PC에 저장됨** 상태를 확인합니다. 저장 실패 시 서버를 실행한 뒤 다시 저장합니다.
- Figure·구조식을 누르면 확대됩니다. 원문 PDF/SI와 페이지 근거는 앱의 페이지 뷰어에서 확인할 수 있으며, 원본 파일 링크도 제공합니다. 브라우저 PDF 플러그인에 의존하지 않도록 원문 페이지 이미지를 함께 제공합니다.

## 새 논문 수집

**논문 카드 → 수집 관리**에서 발행일 범위를 확인하고 **6개 분야 수집**을 누릅니다. Europe PMC에서 6개 분야를 모두 검색해 제목·저자·저널·발행일·DOI/PMID·원문 Abstract를 저장합니다. 인터넷 연결이 필요하며 유료·공개 논문 모두 후보에 포함합니다. 첫 날짜 범위는 변경 가능한 최근 30일이며 자동 수집 주기는 아직 설정하지 않았습니다. 수집 관리 주소는 `#/collection`, 카드 피드는 `#/discover`입니다.

- 분야별 검색식과 진행·실패 내역을 화면에서 확인합니다. 모든 검색 결과 페이지를 순회하며 수집 편수를 임의로 제한하지 않습니다.
- 검색 출처는 Europe PMC의 MED·PMC·PPR이며 특허 등은 제외합니다. 제목·초록의 검색어 일치가 기준이므로 관련 후보를 넓게 모으는 단계이고, 의약화학·신약개발의 모든 논문을 빠짐없이 수집한다고 보장하지 않습니다. 전문 분야의 누락·잡음은 실제 후보를 보며 검색식을 조정하고 출처를 보완합니다.
- DOI·PMID·출처 ID로 중복을 합치고 여러 분야 태그를 유지합니다. 같은 기간을 다시 수집하면 기존 후보를 갱신하고 뒤늦게 등록된 후보를 추가합니다. 선택한 발행일 범위 밖의 지연 등록 논문은 더 넓은 기간으로 다시 수집해야 합니다.
- 후보 목록은 기본적으로 6개 분야를 번갈아 보여줍니다. 분야별 발행량을 같게 만들지는 않으며, 한 논문은 목록에 한 번만 표시합니다. 검색·분야 필터·최근 발행순으로 변경할 수 있습니다.
- 후보의 분야는 **검색식 일치**이고 중요도 판정은 아닙니다. 이 단계는 원문 Abstract와 메타데이터 확인이며, 기존 라이브러리의 검토된 카드·브리핑과 구분합니다.
- 기본 목록은 원저 후보이며 Review·Preprint 보류·확인 필요·기타를 따로 볼 수 있습니다. 출판 유형과 제목·초록으로 분류하고, 초록에서 추정한 원저는 ‘잠정’으로 표시합니다. Journal Article만으로 원저라고 확정하지 않으며 불확실한 후보도 보존합니다.
- 원저·Review에서 **현재 N편 원문 가져오기** 또는 개별 **원문 가져오기**를 누르면 본문을 자동으로 요청·저장합니다. 한 번에 현재 페이지 최대 24편을 처리하는 화면 단위이며 주간 선정 편수나 자동 실행 주기는 아닙니다.
- Europe PMC의 본문 XML을 먼저 확인하고, 없으면 DOI가 연결하는 출판사 페이지에 현재 PC 네트워크로 접근합니다. 논문 식별자와 본문 영역이 확인된 XML/HTML 텍스트만 ‘본문 확보’로 표시합니다. OA 여부는 후보 선정이나 요청의 필수 조건이 아닙니다.
- **본문 읽기**에서 확보한 텍스트·출처·확보 시각을 확인합니다. 차단·초록 페이지·PDF만 제공되는 경우에는 초록을 남기고 **학교 원문 열기** 링크를 제공합니다. 연결 오류는 재시도로 구분합니다. 브라우저에서 원문을 읽을 수 있더라도 자동 요청은 막힐 수 있으며, 자동 확보 실패가 학교 구독 부재를 뜻하지 않습니다.
- 본문 텍스트를 DB에 보관하므로 다시 읽을 때 다운로드가 필요하지 않습니다. 이미 확보한 본문은 재사용하고 실패한 요청은 다시 시도할 수 있습니다. 본문 가져오기와 아래의 **브리핑 자료 준비**는 구분합니다. 브라우저 로그인·쿠키를 가져오지 않습니다.
- 일부 분야에서 실패해도 이미 수집한 후보는 보존됩니다. **실패한 분야 재시도**는 해당 기록의 같은 발행일 범위에서 실패·미실행 분야만 다시 검색합니다. 서버 종료로 중단된 실행도 재시작 후 표시되어 이어서 확인할 수 있습니다.

교내 사용은 연세대학교를 기준으로 합니다. 후보 수집은 공개 검색 API이므로 학교 계정이 필요하지 않습니다. 2026-09-21 시범 평가에서 교내 브라우저의 JCR 및 일부 ACS·IEEE 원문 접근을 확인했습니다. 모든 저널의 구독이나 자동 다운로드·JCR API 권한을 확인한 것은 아닙니다.

## 준비한 자료에서 카드·브리핑 읽기

새 PK 논문 1편은 현재 Codex에서 준비 자료를 읽어 작성하고 독립 검토한 뒤 앱에 연결했습니다. **수집 관리 → 카드 보기 → 상세 브리핑**으로 읽으며, 상태는 **일부 검증 · 초안**입니다. 본문·그림·SI의 확인 범위와 원시 데이터·코드 미재현을 구분합니다. 기존 14편을 보존해 Library에는 총 15편이 있습니다.

자료 준비 버튼 자체가 글을 생성하지는 않습니다. 새로운 후보 전체를 앱이 계속 작성하는 외부 모델 연결은 아직 없으며, 이번 생성·게시 기록은 [data/generated/README.md](data/generated/README.md)에 설명합니다.

## 브리핑 자료 준비

수집 관리에서 원저·Review 후보의 **브리핑 자료 준비**를 누릅니다. PMC 공개 구조화 자료의 본문·표·원본 그림·원문 캡션·보충자료를 연결하고, 출처 URL과 파일·텍스트 해시를 포함한 생성 입력을 저장합니다. 원문 뷰어나 다운로드 창은 자동으로 열지 않습니다.

- **준비 중 → 생성 대기**: 현재 지원하는 자료의 확보·추출과 연결이 끝난 상태입니다. 내용은 여전히 **검토 전**이며, 자동 작성이나 Library 게시는 아직 연결하지 않았습니다.
- **일부 미확보 · 자료 확인 필요**: 본문은 준비했지만 누락된 그림·SI, 확인할 수 없는 자료 수, 자동 변환하지 않는 형식 등이 남아 있습니다. **준비 자료 보기**에서 확보 수·입력에 포함된 수·이유를 확인하고 재시도할 수 있습니다.
- **자료 준비 실패**: 사용할 본문을 확보하지 못했거나 준비 과정이 실패했습니다. 학교 원문 링크는 유지합니다. 서버가 종료되어 작업이 중단되면 재시작 후 중단 상태를 표시합니다.
- 표는 행·열 구조를, PDF SI는 쪽별 텍스트를 보존합니다. 이미지의 시각 해석, PDF 표 배치·수식의 정확성, 과학적 내용 검토는 별도 단계입니다. ZIP·Office 문서·데이터 파일은 원본을 보관하고 자동 해제·실행하지 않습니다. 스캔 PDF나 텍스트 없는 쪽은 확인 필요로 남깁니다.
- PMC 공개 자료가 없으면 기존 본문 확보 경로로 텍스트를 준비하되, 그림·SI의 완전성은 미확인으로 둡니다. 학교 구독 PDF를 자동 다운로드하는 범용 출판사 연동은 구현하지 않았습니다.
- 준비된 입력·파일을 재사용하기 전에 해시를 확인합니다. 작업은 DB당 하나씩 진행하며, API의 최대 24편은 작업 단위일 뿐 선정 편수나 운영 주기가 아닙니다. 파일당 50 MB·논문당 총 150 MB·100개 파일, PDF 500쪽 등 처리 한도를 넘으면 이유를 표시합니다.

API: `POST /api/preparation` (`candidateIds`), `GET /api/preparation` (진행 상태), `GET /api/preparations/<id>` (자료 범위), `GET /api/preparation-input/<id>` (생성 입력). 자료를 열어도 검토 완료로 바뀌지 않습니다. **생성 비교**의 두 시범본과 기존 Library는 보존합니다.

## 시범 평가

왼쪽 **시범 평가** 또는 [평가 화면](http://127.0.0.1:8765/#/evaluation)에서 6개 분야별 원저 2편씩, 총 12편을 확인합니다. 기존 후보 중 기준을 시험하기 위해 고른 사례이며 상위 12편이나 자동 선정 결과가 아닙니다. 9월 21일 평가 당시 11편은 본문 관련 절, 1편은 초록을 검토한 기록이며, 현재 상세 브리핑 전체의 검증 완료를 뜻하지 않습니다. 화면은 분야 필터, 논문 제목·요약·간략한 참고 점수, IF·인용수와 원문 링크만 표시합니다. 세부 배점·항목별 근거·감점 설명은 화면에서 제거했으며 평가 자료와 보고서에 보존합니다.

참고 점수는 `59.5 / 70 · 잠정`처럼 확인한 항목의 배점으로 표시하고 100점으로 환산하지 않습니다. 내용 평가가 끝나지 않은 논문은 낮은 숫자 대신 **평가 중**으로 표시합니다. 점수로 논문을 자동 제외하지 않습니다.

- 합의한 비중: 내용 60점, 보정 인용 영향 20점, 최근 인용 증가 10점, 저널 10점. 새 기준 v2에서는 새로움·근거·재현 가능성·활용 가치에 15점씩 배정하고, 확인된 강점에 따라 0·5·10·15점으로 시험 평가합니다. 기존 20개 조건은 점수 없는 근거 기록으로 남깁니다.
- 불공정 비교·검증 부족 등은 별도로 감점하지 않고 원문 근거를 표시합니다. 코드·데이터가 명시적으로 비공개이고 대체 재현 경로도 없을 때만 논문당 3점을 시험적으로 차감합니다. 대체 경로가 확인되면 면제하고 미확인일 때는 감점을 보류합니다. 요청 시 제공·코드 미생성·본문 미확보만으로 감점하지 않습니다.
- 2025 JCR의 실제 JIF와 분야 백분위를 10개 저널에서 확인했습니다. 복수 분류는 모든 분류 백분위의 중앙값을 시험적으로 사용합니다. JIF 자체를 논문의 품질 점수로 취급하지 않습니다.
- OpenAlex 조회 당시 11편은 인용 0회, Dockformer는 3회였습니다. 신규 논문의 인용 점수는 유예하고, 이전 관측값이 없는 최근 증가량은 미평가로 둡니다. NCS-1은 동일 DOI의 OpenAlex 기록 두 개가 서로 다른 백분위를 제공해 표시합니다.
- 미확인을 0점으로 채우거나 확인한 항목을 100점으로 환산하지 않습니다. 총점과 순위는 미확정이며 불확실한 논문도 표시합니다. v2 본문 내용 점수는 40–55/60점, 초록만 확인한 MetaVision은 새로움 10/15점만 평가했습니다. popPK는 비공개 데이터가 확인됐지만 대체 재현 가능성 때문에 감점 판정을 보류했고 현재 차감은 없습니다.
- 배점·지표는 기준을 드러내기 위한 것이며 과학적으로 검증된 품질 척도는 아닙니다. 개인 환경에서 재현을 실행한 것은 아닙니다. 세부 척도와 3점 감점 폭은 조정 가능한 시험 규칙이며 `data/pilot/SCORING_V2.md`에 기록합니다.
- 평가와 지표는 검토 당시의 저장 자료입니다. 새로운 후보의 자동 평가·JCR 자동 연동·정기 수집은 아직 구현하지 않았습니다. 현재 결과는 `data/pilot/PILOT_REPORT.md`, 이전 결과는 `data/pilot/PILOT_REPORT_V1.md`에 기록합니다.

읽음·저장·메모는 브라우저 저장소가 아닌 SQLite 파일에 보관되므로 앱을 종료하고 재시작해도 유지됩니다. 서버를 종료한 뒤 `data/paper-radar.sqlite3`를 복사하면 개인 기록을 백업할 수 있습니다. 다른 PC로 옮길 때는 논문 JSON과 자료도 필요하므로 프로젝트 폴더 전체를 함께 보관하는 것이 간단합니다.

기존 시안의 브라우저 `localStorage` 메모는 자동 이전되지 않습니다. 필요하면 기존 시안에서 내용을 복사해 앱의 메모에 저장합니다.

Git 저장소에는 코드·논문 카드·시범 평가 자료와 화면에 필요한 원문·이미지를 포함합니다. 개인 기록과 수집 후보가 들어 있는 SQLite DB, 자동 준비 자료, 가상환경, 임시 파일·로그는 제외합니다. 새로 복제한 PC에서도 기존 사례 2편과 새 카드·시범 평가 12편을 바로 볼 수 있습니다. 수집 후보·본문은 백업한 DB를 복원하고, 준비한 생성 입력까지 복원하려면 `public/assets/prepared/`도 함께 복사합니다.

## 논문 데이터 수정

논문마다 HTML을 새로 작성하지 않습니다. 기존 사례는 `data/papers/*.json`, 시범 12편의 카드와 상세 내용은 각각 `data/cards/*.json`, `data/briefs/*.json`에서 관리합니다. 확인한 범위는 `data/brief-reviews.json`에 별도로 기록합니다. 파일은 UTF-8 JSON이며, 변경 후 서버를 재시작하고 브라우저를 새로고침합니다.

| 필드 | 역할 |
| --- | --- |
| `id` | 논문별 고유 식별자. 개인 기록과 연결되므로 기존 값을 유지합니다. |
| `metadata` | 영어 원제, 한글 번역, 저자·저널·발행일·DOI, 분야·태그, 검토 상태, 자료 URL·확보 상태·라이선스 |
| `abstract` | 전문 번역 `paragraphs`, 원문 근거 `source`, 원문 페이지 이미지 `pageImage` |
| `card` | 목적, 방법→결과, 대표 이미지, 동향상 의미, 연구 적용·한계, 선정 이유 |
| `tabs` | `summary`, `overview`, `methods`, `evidence`, `memo`의 섹션 배열 |

각 섹션은 `title`과 `blocks`로 구성됩니다. 지원 블록은 `paragraph`, `callout`, `list`, `pairs`, `table`, `details`, `image`, `figure`, `ligands`, `links`, `grid`입니다. 기존 사례 JSON과 `data/briefs/`를 구조 예제로 사용합니다. 짧은 강조·첨자·출처 링크에는 `b`, `strong`, `em`, `i`, `br`, `a`, `sub`, `sup`, `code`만 사용할 수 있습니다.

발행일은 `YYYY-MM-DD` 형식으로 입력합니다. 로컬 자료 URL은 원본 자료의 경우 `/reference/...`, 앱용 자료는 `/assets/...`를 사용합니다. 검토된 브리핑 JSON은 고유 `id`와 DOI를 확인해 중복 없이 등록합니다. 자동 수집 후보는 별도 테이블에서 식별자 중복을 제거하고, 이미 라이브러리에 있는 DOI를 표시합니다.

주요 주장의 Figure·페이지 근거, 원문 caption, 라이선스와 검토 상태를 함께 유지합니다. 저자 Abstract의 주장과 브리핑의 해석·적용 제안을 구분하고, 원문에 없는 조건을 추정하지 않습니다. Sung 사례의 별도 SI·Source Data는 미확보/미검토 상태로 표시되어 있습니다.

`acquired`는 파일 확보 여부, `checked`는 실제 검토 범위입니다. `fulltext` 확보 이력만으로 검토 완료를 표시하지 않습니다. `held`로 기록된 상세 내용은 보류 안내로 대체하고 카드·개인 기록은 보존합니다. 그림 파일명의 순번은 원래 Figure 번호와 다를 수 있으므로 `public/assets/briefs/<candidateId>/sources.json`의 label·figureId·path를 대조합니다.

## 확인과 범위

`#/rounds`의 **이번 회차**는 여섯 분야별 새 원저 한 편씩만 보여줍니다. 선정 이유·잠정 점수·자료 준비 상태를 확인하고 개별 또는 여섯 편의 자료 준비를 시작할 수 있습니다. 첫 회차는 초록 기반 선정까지 완료했으며 새 브리핑은 아직 없습니다. 검색 범위와 원본·미확인 사항은 [회차 기록](data/rounds/README.md)에 있습니다. 회차 조회는 원문 확보나 AI 작성을 자동 시작하지 않습니다.

서버·저장 기능의 자동 검증:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`tools/`의 추출·자료 생성 스크립트는 콘텐츠를 준비할 때 사용하는 보조 도구입니다. 일부는 PDF·이미지 처리 패키지가 필요하지만, 이미 포함된 데이터와 자료로 앱을 실행할 때는 필요하지 않습니다.

원문 페이지 뷰어는 `public/assets/documents/manifest.json`과 미리 생성한 WebP를 사용합니다. 현재 18문서·458페이지이며, 기존 3문서에 시범 논문의 본문 8개·SI 7개를 추가했습니다. 원본 PDF도 그대로 유지합니다. 재생성 도구 `tools/render_source_documents.py`는 Pillow와 pypdfium2가 필요합니다. 렌더링·열람 가능 여부와 논문 내용 검토 여부는 별개입니다.

실제 자동 테스트·브라우저·재시작·자료 열람의 최신 확인 범위는 [VALIDATION.md](VALIDATION.md), 논문별 검토 범위는 [BRIEF_VERIFICATION.md](BRIEF_VERIFICATION.md)에 기록했습니다.

이 버전은 카드 우선 탐색·상세 브리핑·읽음·저장·메모, Europe PMC 후보 수집, 본문·표·그림·SI 생성 입력 준비를 제공합니다. 새로운 후보의 상시 AI 생성·정기 수집·기간별 동향 비교는 다음 단계이며, 유료 API·로그인·배포는 연결하지 않았습니다.
