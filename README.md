# Paper Radar

2026-10-01 승인된 정리 후 기준입니다.

## 유지한 기능
- AdaptiveFlow 2026·Sung 2025 두 기준 사례의 핵심 요약·심층 분석.
- 논문 목록·검색·분야 필터·읽음·저장·메모.
- 원문 PDF·그림 뷰어와 작성 지침 `BRIEFING_GUIDELINES.md`.
- `#/workflow`에서 Choi 2025 원저/추가 읽기 RIS 파일 다운로드.

## 작업 흐름
사용자가 리뷰 또는 원저 PDF 제공 → Codex에서 원문 검토·핵심 요약과 관련 문헌 RIS 작성 → 사용자가 Zotero에서 PDF 확보 → Codex에서 핵심 요약 → 선택한 논문의 심층 분석.

PDF 업로드와 요약 자동 생성은 아직 앱에 통합되지 않았습니다. Zotero 폴더 매칭은 아래 PDF 연결 기능에서 지원합니다. 원본은 Dropbox/Zotero에 유지하고 향후 파일 경로를 연결하는 방향입니다. 지금은 Codex와 함께 자료를 확인하고 결과를 등록합니다. 파일 확보와 과학적 내용 검토는 서로 다른 상태입니다.

## 제거한 기능
자동 수집·후보 선정·평가 점수·회차·생성 비교·직접 PDF 자동 다운로드와 관련 시험 데이터, 이전 12편·PK 시험 콘텐츠, Review Radar 잔여 자료, Niazi 작업, 과거 임시 백업.

Git 이력과 실행 환경은 유지했습니다. Dropbox/Zotero 원본과 프로젝트 외부 Downloads 파일은 변경하지 않았습니다.

## 실행
`Paper Radar.cmd` 또는 `.venv/Scripts/python.exe server.py`.
주소: http://127.0.0.1:8765/
검증: `.venv/Scripts/python.exe -m unittest discover -s tests -p test_server.py`

## 파일
- `server.py`: 자료 제공·로컬 메모 저장
- `public/app.js`, `public/styles.css`: 화면·뷰어
- `data/papers`: 두 기준 사례
- `reference`, `public/assets`: 두 사례가 참조하는 원문·그림·페이지 이미지
- `exports/choi-2025-aiml-special-issue`: 현재 RIS 작업
- `CLEANUP_MANIFEST.json`: 승인된 삭제 대상 기록

## 작업 관리 (2026-10-01)
`#/workflow`에서 작업별 제공 논문·핵심 요약·관련 문헌·RIS와 작성 상태를 확인합니다. 현재 Choi 특집 1개 작업(원저 7편/추가 읽기 7편)이 등록돼 있습니다. `data/workflows/*.json`에 Codex가 검토한 작업과 결과 연결을 등록하며, 사용자가 새 작업을 업로드하거나 화면에서 내용을 편집하는 기능은 아직 없습니다.

Choi 원본 PDF는 기존 감사 기록의 경로와 SHA-256을 확인한 후 복사 없이 제공합니다. 관련 원저 PDF 폴더 검사와 매칭은 아래 PDF 연결 기능에서 지원합니다. 핵심 요약·심층 분석 연결 ID가 실제 앱 논문에 존재할 때만 열람 링크를 표시합니다. Choi Editorial의 요약은 작성 대기이며, 관련 논문은 본문 참고문헌이 아닌 공식 특집 수록 문헌입니다.

## Zotero PDF 연결 (2026-10-02)
작업 화면의 **PDF 연결 확인**을 누르면 `C:/Users/USER/Dropbox/Zotero_PDF`와 하위 폴더를 읽습니다. 자동 감시나 다운로드 요청은 하지 않습니다. Dropbox 온라인 전용 파일은 읽을 때 로컬로 내려받아질 수 있습니다.

- 첫 페이지 제목·DOI가 모두 맞는 단일 문서를 자동 연결합니다. 참고문헌 영역의 DOI는 식별에 사용하지 않습니다.
- 제목만 일치하거나 서로 다른 판본이 여러 개면 확인 필요로 표시합니다. 후보 PDF를 확인한 후 **이 PDF로 연결**할 수 있습니다.
- 동일 파일 사본은 해시로 묶습니다. 원본을 복사·이동·변경하지 않고 경로·해시·쪽 수와 확인 근거만 SQLite에 저장합니다.
- PDF를 읽지 못한 경우 오류를 표시하고, 일치 파일을 찾지 못한 논문을 섣불리 PDF 없음으로 확정하지 않습니다. OCR은 포함하지 않습니다.
- PDF 링크를 열 때 저장한 해시와 대조하며, 변경·이동된 파일은 재검사가 필요합니다. 사용자가 확인한 동일 파일은 재검사 후에도 선택을 유지합니다.
- PDF 확보/연결과 내용 검토/핵심 요약 작성 상태는 별개입니다. 이번 단계에서 분석을 생성하지 않습니다.

테스트: `.venv/Scripts/python.exe -m unittest discover -s tests -p "test_*.py"`

## 생성 도구와 요청 저장 (2026-10-02)
- 생성 도구: Review 추출기, 핵심 요약 생성기, 심층 분석 생성기.
- 라이브러리: 핵심 요약 라이브러리와 전체/저장/읽지 않은 논문 필터.
- 생성기에서 현재 등록·연결된 PDF를 선택하고 생성 요청을 저장합니다. 별도 AI API 연결이나 자동 실행은 없습니다. 이후 Codex 채팅에서 “저장한 생성 요청 처리해줘”라고 요청해 처리를 시작합니다.
- `generation_requests.py`와 `public/generators.js`, GET/POST `/api/generation-requests`가 요청을 관리합니다. 기존 로컬 SQLite의 `generation_requests` 테이블에 종류·논문 식별자·원본 경로·해시·요청 시각·처리 대기를 저장합니다. PDF는 복사하지 않습니다.
- 동일 논문·종류·PDF 해시 요청은 중복 저장하지 않습니다. 저장은 내용 검토나 작성 완료를 의미하지 않습니다. 현재 임의 PDF 업로드와 완료 처리 화면은 없습니다.

## Codex 버튼 생성 (2026-10-02, 앞선 수동 요청 방식 대체)
생성 버튼은 기존 Codex ChatGPT 로그인으로 로컬 `codex exec`를 실행합니다. 별도 API 키는 사용하지 않습니다. 서버는 한 번에 한 논문씩 준비→작성→형식/인용 검증→별도 Codex 근거 검토를 진행합니다. 이전 저장 요청은 자동으로 시작하지 않습니다. 실패/보류는 원인을 표시하며 같은 논문을 선택하고 생성하면 재시도합니다.

- `BRIEFING_GUIDELINES.md`: 핵심 요약/심층 분석의 목적·깊이·필수 항목·완료 기준.
- `codex_generation.py`: 읽기 전용 Codex 실행, 원본 해시 확인, 페이지 이미지·텍스트 전달, 검증/근거 검토. 모델은 기존 Codex 설정을 사용합니다.
- 요청·초안·검토 결과·완료 결과: `data/paper-radar.sqlite3`의 `generation_requests`.
- 페이지 이미지·프롬프트·실행 기록: `.runtime/generation/<요청번호>/`. 결과의 그림 표시에도 필요하므로 이 폴더를 임의로 지우지 않습니다. 원본 PDF는 복사하지 않습니다.
- 완료 핵심 요약/심층 분석은 각각의 라이브러리에서 분리 표시합니다. 표시되는 검토 상태는 Codex 검토이며 사람 검토 완료가 아닙니다.
- 한 요청 최대 30편. 원문 40쪽 초과 또는 텍스트 추출 불완전 시 보류. SI·Source Data 자동 확보/검토는 하지 않습니다. 실행당 20분 제한. 재시작 중이던 작업은 실패로 기록하고 자동 재실행하지 않습니다.
- 서버 프로세스가 사용자 Codex 상태 폴더에 접근할 수 있어야 합니다. 앱 버튼은 로컬 요청만 허용하며 임의 실행 명령/파일 경로를 받지 않습니다.


## 심층 분석의 표·그림 자동 편집
- 근거 검토 뒤 `visual_generation.py`가 탭별 표·설명·그림 배치와 원문 그림 영역을 생성합니다.
- 진행 상태: 표·그림 배치 중 → 표·그림 근거·발췌 검토 중 → 완료 또는 보류. 모델 호출은 기존 Codex 로그인으로 수행하며 별도 API 키를 사용하지 않습니다.
- 표 구조·근거 인덱스·5개 탭·그림 좌표를 검사하고, 발췌 이미지까지 별도로 검토합니다. 검토 실패 시 완료로 게시하지 않습니다.
- 원문 보고서는 보존하며 화면용 `presentationPlan` / `presentationTabs` / `presentationReview`를 결과에 함께 저장합니다. `layout*.json`, `layout*-log.txt`, `figure-*.png`는 해당 요청의 `.runtime/generation/<번호>/`에 저장됩니다.
- 자동 검토는 사람 검토가 아닙니다. 새로운 유형의 논문이나 화면 변경은 실제 브라우저에서도 확인해야 합니다.
